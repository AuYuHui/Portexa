# MT4 原生协议验证结果

核验时间：2026-11-11 凌晨（Asia/Shanghai）。范围为用户授权的读取操作，不发送交易请求，不公开凭据、接入地址或报文。

工程整理后，原生实现位于独立模块 `packages/mt4`，联网命令位于 `cmd/mt4probe`，测试集中存放。本文保留初始线上验证证据；目录重构另通过公开接口、CLI、协议及采集测试，并对两组私有向量完成离线回归，没有重新登录真实服务。

## 结论

**原生 Go 路线的最小 PoC 已通过。** 同一份可审阅源码已在 macOS arm64 和真正的 Linux arm64 容器中直接连接 DLSMarkets、DPrime，完成新生成的握手、挑战响应、会话确认、账户及历史读取。Linux 容器由 `scratch` 构建，只有静态 Go 可执行文件，没有 MT4、Wine、EA、手机或第三方账户服务。原始数据和测试日志仅保留在 `.local/`。

这证明指定版本、两家已测平台的路径可独立实现；不代表 MT4 协议全部还原，也不代表账户聚合产品已完成。

## 已实现与核验的方法

源码：[原生 Go 客户端](../../packages/mt4/README.md)。依据：[移动客户端静态分析](mt4-mobile-auth-static.md)。

1. C28 的账号、密码派生字段、端序及反馈编码已重建。两组私有向量中，新生成的 C28 与官方样本逐字节一致。
2. 服务端连续流、非零挑战分支、八种算子、特殊摘要、AES-CBC 和尾部反馈编码均已实现。摘要及块算法先与原函数的合成离线执行交叉核对。
3. 动态特征程序已化简为小型整数 VM；不在运行时调用官方二进制。认证记录顺序、伪随机填充、type3 key 演化、SHA-1 proof 及 type10 计算均已复现；两组完整 C18 与官方捕获逐字节一致。
4. 线上依次校验 `0x10` 配置、`0x08/0x0a` 表、`0x21` 可选状态、`0x22` 历史、`0x1e` 账户。所有请求/响应保持各自连续流状态，LZO 输出长度和结构边界严格检查。
5. 账户解析余额、信用、杠杆及原始指示字段；224字节订单解析订单号、品种、方向、数量、SL/TP、佣金、隔夜费、利润和税费，真实值不写入终端输出。

`0x21` 非零状态只有状态字节，官方调用者会继续后续同步。两家实际均返回1；这不被误判成整条登录失败，也不会继续读取不存在的计数和主体。`0x08/0x0a/0x22` 的状态1同样无主体，但表示未变化，不能算作新取得了完整数据。

## 解决的关键差异

账户请求的 type13 使用一组公开的移动客户端兼容字段：应用标识、签名 team 标识、文件名、版本及合成系统版本。完全自定义这组字段时，两家账户请求均等不到首个状态；使用兼容字段后通过。该测试证明**整组元数据影响兼容性**，没有逐字段证明哪一个值是必要条件。这里的 `devid` 来自公开应用签名 team，不是用户设备ID；没有复制真实硬件、机器名称、消息ID或用户编号。

fresh 安装随机材料和用户编号0已在两家通过；无需重放真实设备材料。单连接 flags2 已通过，无需参考客户端的第二连接线程。配置名称尾64字节是窄字符，早期误按UTF16提取的错误已修正；未启用原客户端的名称检查绕过。

## 仍未验收

- Mac 已锁屏，最后的官方 UI 逐项数值对照未能进行。余额/信用/杠杆已有源代码字段依据、真实解码和有限性检查，**尚未声称与 UI 逐项一致**。账户响应中也未定位独立的账号回显；不能把本地请求账号当作服务端回显证明。
- DLS 的投资者指示为0，与用户提供投资者密码的描述未形成独立对应。保留原值和未确认状态；没有尝试交易来探测权限。DPrime 指示非零也不用于推断所有权限组合。
- 当前订单中，buy/sell 的 `time20` 均为合理非零秒值，`time40` 均为0；历史中 `time20<=time40`。这些证据支持开/平仓解释，逐条 UI 时间、时区和金额对照仍待完成。
- 净值、币种、保证金等完整账户字段，实时订阅、历史完整性、断线增量恢复、自动服务器发现、OTP、零挑战旧分支和其他 build 尚未实现或验证。
- 未以错误密码重复请求真实账户；错误结构、截断、边界及摘要等反例由合成测试覆盖。
