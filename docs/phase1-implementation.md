# Portexa 第一阶段实施规格

第一阶段交付单用户密码登录、可信服务器及账户接入、60秒周期快照和账户看板，沿用[产品方案](product-plan.md)。后续补充服务器当日利润、胜负明细、保证金水平、历史回填与自动识别出入金，支持人工校正，见[使用口径](account-statistics.md)。SDK 仅增加原始备注输出，收益率和回撤属于后续阶段。

## 服务与存储

Go 标准 HTTP 服务提供同源 API 与构建后的 Vue 静态资源。SQLite 使用 modernc 驱动及 GORM，单写连接、最多4个读连接，使用版本化 STRICT 迁移，不使用 AutoMigrate。实际引擎版本至少3.51.3。

第一阶段建立登录、服务器、版本化接入点、时区规则、账户、快照运行、资金快照和当前持仓表。任务包含服务器 ID，并由复合外键约束账户及接入点的归属。历史完整原型保留在[数据模型](product-data-model.md)；版本5交付的历史覆盖、订单修订与分类表以编号迁移及[账户统计](account-statistics.md)为准。

运行数据、密钥、备份和静态构建产物位于被忽略的 `.local` 下。凭据密钥文件独立于数据库及数据库备份，文件0600、目录0700。CLI 本地初始化登录密码和密钥，支持本地重置密码及备份；密码不通过命令行参数传入。

## 登录与接口保护

登录密码按 Unicode 字符数校验，至少16个字符。Argon2id 保存带参数和随机盐的密码哈希。会话使用32字节随机令牌，数据库只保存 SHA-256 摘要；默认空闲30分钟、绝对8小时过期，改密和本地重置撤销所有旧会话。

浏览器同源访问，生产 Cookie 设 HttpOnly、Secure、SameSite。修改请求校验配置的 Origin；登录要求 JSON，其他修改请求还须携带与当前会话绑定的 CSRF Token。后台轮询不延长空闲期限，用户交互按节流心跳续期。登录按来源和全局限制尝试频率。

仅登录流程、必要静态资源和最小存活检查允许匿名。登录失效返回401并清空前端 Query 缓存。错误响应只提供脱敏业务错误，不展开 SDK 底层网络错误或 SQL 参数。

本地开发的 HTTP Cookie 仅限显式开发模式和环回监听，开发模式不改变 MT4 目标核验与拨号策略。测试回环目标和合成 Fetcher 仅由测试构造注入，不能通过生产 HTTP 开启。

## API 契约

统一使用 `/api` 前缀，JSON 响应；金额为十进制字符串，缺失为 null。修改请求接受明确字段，拒绝未知字段；无角色、用户名或注册接口。

| 方法与路径 | 行为 |
| --- | --- |
| `GET /healthz` | 最小存活检查，不返回业务或配置 |
| `GET /api/auth/session` | 登录流程初始化，返回登录状态和已登录会话的 CSRF Token |
| `POST /api/auth/login` | 仅密码登录，签发新会话 |
| `POST /api/auth/logout` | 撤销当前会话 |
| `POST /api/auth/touch` | 已登录用户交互心跳，受 CSRF 保护 |
| `PUT /api/auth/password` | 核验原密码并设置新密码，撤销所有会话 |
| `GET /api/overview` | 最近已知资金合计、账户列表、采样范围和缺失状态 |
| `GET /api/servers` | 服务器及接入点状态，不包含凭据 |
| `PUT /api/servers/{id}/time-zone` | 切回自动时间或保存高级手动校正，按规则版本防止覆盖并发修改 |
| `GET /api/server-directory?q=...` | 登录后搜索 MT4 经纪商或服务器，返回短期有效候选 |
| `POST /api/servers/discovered` | 使用服务端候选登记服务器、保存来源及本修订明确风险确认 |
| `POST /api/servers/{id}/discovered-endpoints` | 从同公司、同服务器的候选建立新修订，暂停旧绑定 |
| `POST /api/servers` | 建立服务器及待核验接入点，不拨号 |
| `POST /api/servers/{id}/endpoints` | 建立新接入点修订，停用旧地址并暂停受影响账户 |
| `POST /api/endpoints/{id}/review` | 登记独立核验依据、摘要及该修订的风险确认 |
| `GET /api/accounts` | 返回脱敏账户配置和当前快照状态 |
| `POST /api/accounts` | 加密保存投资者凭据，按请求启用采集 |
| `GET /api/accounts/{id}` | 当前快照、持仓、挂单和同步状态 |
| `PATCH /api/accounts/{id}` | 更新标签、单位确认、凭据、已核验接入点或采集开关 |
| `POST /api/accounts/{id}/sync` | 合并到快照队列，返回202；不在 HTTP 请求内等待 Fetch |
| `POST /api/accounts/{id}/daily/sync` | 合并当日历史需求，沿用独立历史配额及快照让位规则 |
| `POST /api/accounts/{id}/history/sync` | 合并历史回填及重查需求，失败保留已取得的历史 |
| `GET /api/accounts/{id}/funds` | 资金流水有界游标分页，支持仅看待分类 |
| `PUT /api/accounts/{id}/funds/{ticket}/classification` | 按源记录与分类版本追加人工确认 |
| `GET /api/accounts/{id}/snapshots` | 有上限的按采样时间查询，用于最近采集记录 |

读取接口只允许既定的日期、采样时间或订单号等排序键，拒绝金额排序参数；不能把全部历史读入 Go 后再排序分页。新增历史金额排序须在第二阶段明确可排序数值键的精度、范围和溢出验证。

## 可信账户与快照

新接入点为 pending。核验依据、摘要、reviewed 状态、风险接受记录、账户固定关系及采集开关全部满足后才可调用 SDK。更新地址必须建立新修订，不继承旧风险接受。正常轮询和重连复用有效修订的记录。

默认登记流程使用[服务器发现](server-discovery.md)：地址及证据由服务端目录查询取得，浏览器只提交候选 ID、接入点序号和明确风险确认。选择后原子保存来源及该修订的核验/确认记录。手动高级路径继续先登记 pending，再填写独立证据。目录查询不登录账户，也不将候选自动视为可发送凭据的授权。

凭据用 AES-256-GCM 加密，AAD 绑定账户、服务器、接入点及凭据版本。HTTP 从不回读凭据或密文。账户配置增加版本号，接入点、凭据、单位或采集开关变化后取消旧任务；提交前再校验版本。

快照独立10并发，每账户最多一个 Fetch，默认60秒并均匀错开。调度合并重复需求，超时或连接错误按60、120、300秒退避；SDK 拒绝、资源超限或配置不支持时停止重复尝试并提示。SDK 成功、会话及账户标记完整后，资金、当前持仓、指针与运行状态一次提交；失败保留旧值。数据库无法记录任务状态时停止调度并退出服务，修复存储并由监管进程重启后将遗留运行标记中断，避免账户永久卡在执行锁。

原币数值始终保留；仅确认过的 USD、USC 进入美元合计。快照记录采集开始和完成时间，合计显示实际采样范围，过期或缺失账户不当作零。未知时区的持仓时间明确显示为服务器墙钟。

## 交易事件时间校准

版本4增加持仓消失观察、服务器校准状态和独立校准运行表。只有同配置、同接入点的两次成功快照才能形成观察；以先前 Fetch 开始至后续 Fetch 完成作为 UTC 边界，窗口最长3分钟，每次快照最多记录128笔候选。首次发现的历史订单、仍在持仓的订单和取消的挂单均不产生证据。

存在候选时，在所有支持的当前 UTC 偏移范围内请求原始历史，不依赖已经确认的时区。完整响应、准确覆盖及订单号/品种/买卖类型/开仓时间一致后，平仓墙钟必须唯一落在某个15分钟整数倍偏移对应的 UTC 窗口；15分钟内未确认的候选不继续贡献新证据。最近一致序列至少3个不同订单、覆盖至少2次持仓消失快照后采用。

优先级为明确手动校正、有效事件校准、已收录官方规则、等待新事件。校准证据24小时有效，以实际观察时间续期；重放历史不会续期，相同偏移的新事件不会反复创建规则版本。冲突重新累计，已知夏令时切换前或横跨切换的证据不用于切换后的时钟。规则变化后当日汇总重新采集，不重用旧规则结果；未知服务器不会猜测零时区。

校准和当日历史共用2个历史名额，同账户与快照互斥，数据库触发器同步约束三类运行；距离快照至少25秒才准入、快照前5秒结束或让位。校准失败单独退避或暂停，不修改资金快照的采集开关与失败计数。启动、备份恢复会中断遗留校准锁。SDK 不增加业务推断或未经核验的实时时钟字段。

## 页面与验收

提供登录、总览、账户详情和设置页。总览包含资金卡片、账户表格、筛选和同步状态；详情区分持仓与挂单；设置完成服务器核验、账户接入、改密和采集控制。Vue Query 管理 API 数据，Pinia 只存会话与偏好，Reka 负责对话框交互，数字使用统一格式和对齐。

验收覆盖匿名拒绝、密码长度、登录限流、CSRF、会话撤销、凭据不回读、未核验目标零拨号、复合外键、并发合并、失败保留旧快照、配置变化取消、金额精度、备份恢复及桌面和移动布局。普通回归只使用合成与回环数据。

历史原子发布单独以真实 Go SQLite 驱动验证1,000、5,000、20,000条修订，记录发布事务 P95、最大耗时和运行环境。未达到100毫秒 P95或1秒上限时，第二阶段优先按独立完整历史覆盖区间拆分发布单元，不拆散同一区间的原子性。这项测量不表示第一阶段已交付历史同步。
