## 交付与边界

- 单用户系统密码登录，无用户名或角色，至少16个字符；本地初始化和重置、Argon2id、会话摘要、空闲与绝对过期、撤销、Origin、CSRF 和登录限流。
- GORM / modernc SQLite / STRICT 迁移，单写队列与4个只读连接，Decimal TEXT；账户、任务和接入点由复合外键约束归属。
- 独立密钥、AAD 绑定和持久化加密次数；服务器修订独立核验与风险接受，变更暂停、取消旧任务并明确重新绑定。
- 默认60秒快照、10并发、每账户1个 Fetch，去重合并、重启恢复、退避及永久错误暂停；失败保留旧快照和持仓，配置变化拒绝旧结果发布。
- Vue 中文登录、总览、账户详情与设置；USD/USC 的最近已知小计、原币分列、真实采样范围、缺失和过期状态。
- Online Backup、完整性/外键验证、7日/4周副本、维护状态；恢复撤销会话并暂停采集，运行锁阻止并行管理覆盖。

首轮交付时 `packages/mt4` 没有修改，历史回填与资金分类尚未实现。后续补充当日报告，并在版本5、6增加交易统计、历史回填、备注输出和自动分类，见本文末节。收益率、回撤、归档与密钥轮换仍未交付。未验证真实经纪商接入、实际服务器容量、真实20秒网络预算、长期磁盘增长或生产 HTTPS 反向代理。UI 的 HTTPS/Cookie 规则已做接口验证，不能代替部署后的证书、代理与出站策略验收。

## 历史原子发布性能

命令为 `make history-performance`。使用产品相同 Go 驱动，在本机临时文件运行[数据模型](product-data-model.md)的完整历史 SQL 原型。STRICT、外键、索引、发布触发器、WAL、FULL 和1000页自动 checkpoint 均开启；暂存每批500行，发布事务包含任务成功、全部当前版本切换和覆盖推进。发布后核对行数与完整性，计时包含 BEGIN/COMMIT，排除暂存准备，不等于端到端导入吞吐。

每场景20次发布，首次场景持续增加新订单，更新场景对同批订单持续追加修订。2026-11-11 06:41 UTC 复测：

| 场景 | 修订数 | 发布 P95(ms) | 最大(ms) |
| --- | ---: | ---: | ---: |
| 首次发布 | 1,000 | 3.53 | 3.56 |
| 更新版本 | 1,000 | 3.76 | 3.84 |
| 首次发布 | 5,000 | 20.04 | 20.16 |
| 更新版本 | 5,000 | 34.97 | 36.10 |
| 首次发布 | 20,000 | 86.00 | 91.81 |
| 更新版本 | 20,000 | **106.71** | **118.47** |

2万条更新超过100ms P95目标，全部低于1秒上限。此前独立首轮也测得该场景 P95=101.77ms、最大105.92ms，因此不能直接接受“万条发布一定满足目标”。

第二阶段按独立完整覆盖区间划分发布单元，以约5,000条修订作为初始规划预算，结合部署机与读写压力复测。超预算先细分区间并重新取得每个子区间的完整响应，再独立原子发布；不发布部分父区间或已知不完整响应。最小区间仍不达标时标记阻塞并单独验收。

第一阶段接口只允许有索引的日期/采样时间/订单号排序，明确拒绝金额排序。金额排序属于第二阶段范围：需可排序数值键及范围/精度/溢出验证，不能用 TEXT 字典序、REAL 或全量加载到 Go 后分页。
