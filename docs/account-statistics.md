# 账户交易统计与自动出入金

账户总览、账户详情均展示当日平仓、胜率、盈利/亏损、累计入金/出金和保证金水平。资金流水默认根据明确备注自动识别，人工只需校正或补充不明确的流水。金额保留账户原币；USC 不在这些指标中除以100。跨账户的美元资金小计继续使用原有确认规则，不平均账户胜率或保证金水平。

账户详情的「单笔最大平仓净亏损」和「单笔最大平仓净盈利」使用当日完整成交历史，与同一份日报按交易服务器日期统计。MT4 按已平仓订单比较，MT5 按平仓成交比较（包括部分平仓）。净额包含该笔成交已报告的费用，保持账户原币，显示单号、品种及服务器平仓时间。没有盈利或亏损时，对应指标显示 `—`。

## 当日统计

“当日”采用已确认的交易服务器自然日，按服务器墙钟的 `[00:00, 次日00:00)` 归属。MT4 对应每条已平仓买卖订单，包含以前开仓、当日平仓的订单。MT5 按入账的成交统计，详见 [MT5 成交与资金口径](#mt5-成交与资金口径)。下表的费用公式以 MT4 为例。

| 指标 | 口径 |
| --- | --- |
| 当日利润 | 所有当日平仓记录的 `Profit + Commission + Swap + Taxes` 之和 |
| 当日盈利 / 净盈利笔数 | 单笔净额大于零的金额之和及记录数 |
| 当日亏损 / 净亏损笔数 | 单笔净额小于零的绝对值之和及记录数 |
| 持平笔数 | 单笔净额为零的记录数 |
| 胜率 | 净盈利笔数 / 所有平仓笔数 × 100%，持平计入分母 |
| 当日结余 | 当日利润 + 余额调整净额，信用金另计 |

无平仓时胜率为 null，页面显示 `—`；完整空日报的金额与笔数为零。版本5之前的日报只知道已保存的净利润、结余和总笔数，胜负明细保持 null，下一次当日采集成功后补齐。费用可能使账面盈利单成为净亏损单，胜负依据净额。

保证金水平在已用保证金有效且大于零时，由后端 Decimal 计算 `账户净值 / 已用保证金 × 100%`，净值包含信用金。零保证金显示“无占用”，缺失显示 `—`。API 百分比为十进制字符串，保留8位除法精度，页面四舍五入至两位。MT5 原生快照对无挂单且规则完整的 CFD Leverage 持仓计算已用保证金。规则缺失或暂不支持时显示 `—`，账户杠杆单独展示。

## 历史回填与自动识别

启用采集、已有当前单位快照且服务器日期就绪后，后台自动回填可返回的历史。MT4 按服务器自然日查询，当日区间每5分钟重查。MT5 只查询已过去的区间，每次查询最多到当前服务器时间。最近一小时的区间每5分钟重查，当日更早且已完整覆盖的区间每小时重查。已回填的往日区间约每日轮转重查。停机跨日会补建缺口窗口，详情也可点击“回填 / 重查历史”。服务器已经删除或不再返回的旧记录无法由客户端恢复。

当日历史拆成多个窗口时，MT4 优先处理覆盖最近两小时且已经开始的区间，MT5 优先处理覆盖最近一小时的区间。已排队的当日重查仍在执行时，重复点击沿用本轮队列，已完成的区间保留其调度进度。

MT5 历史回填为有备用点的连接、握手和账户同步阶段分配较短预算。切换前至少保留 8 秒，时间不足则将原区间留待下次满足调度条件时重试。拉取成交超时会直接拆成较小区间，同一优先级先补采这些区间。历史任务仍在资金快照前让位，只发布已完整取得的区间。

规则 `balance-comment-v3` 根据备注中的明确标识识别外部入金、外部出金、返佣、费用、分成、内部转账和调整。支持 Deposit/入金、Withdrawal/出金、Rebate/返佣等；方向必须与类别一致，信用记录始终单独处理。只凭金额正负不能区分外部出入金与返佣等其他余额变动。

MT4 将余额流水标为 `Command=6`（balance），信用为7；服务端备注由独立的 `Comment` 字段保留。`D(DIN…)` 配合正金额识别入金，`W(DOUT…)` 配合负金额识别出金，编号部分必须为数字且括号完整。DIN/DOUT 属于已识别的券商备注格式。[MT4 历史字段说明](https://www.metatrader4.com/en/trading-platform/help/overview/terminal/terminal_account_history)

DPrime 备注规则根据用户确认的券商含义补充，忽略大小写和首尾空白：`dbu` 配合正金额识别入金，`wbu` 配合负金额识别出金，均允许空格分隔的 `#IT` 数字编号；`-PF` 配合负金额识别为跟单分润支出（`profit_share_expense`），允许完整的 `|数字|&数字` 后缀。分润支出不计入累计出金。方向不符、零金额、不完整或混合备注保留待识别，`subs|…` 等尚未确认含义的标识也不自动归类。

自动结果随规则版本校验；读取旧版本结果时使用已经保存的原始备注和费用重新计算，总览、详情及待识别分页保持一致。规则升级无需再次连接 MT4，也不产生虚假的交易源修订；有效人工校正仍优先保留。

空备注、未知标识、同一备注出现多个类别、方向冲突、退款或撤销、文字编码不明确、附带单独费用的混合流水均保留待识别，不自动计入出入金。需要时可在详情点击“补充识别”或“校正”，对照到账记录说明原因。人工校正绑定源修订并优先于自动结果，仍可改回待分类；普通使用无需逐笔打开表单。

规则针对整笔净额，需要拆分的混合流水保持待识别。“收益分析”支持核对两笔已分类的内部转账，并据此计算组合在途资金。[转账与组合口径](analytics.md#资金分类与组合)

“累计入金”和“累计出金”合计当前单位、当前订单版本上自动识别或人工校正的外部资金，出金显示绝对值。返佣、费用、分成、内部转账、信用金和待识别记录不进入这两项。页面分别显示自动识别、人工校正与待识别数量；没有成功历史时为 null，已知区间尚无识别出的外部资金时显示零并保留范围与待识别提示。

历史尚未完整回填时标明“已识别部分”，失败和区间缺口不清空先前成功数据。MT5 展示历史连续覆盖到的服务器时间。当日连续覆盖落后服务器当前时间超过10分钟时标记过期。MT4 仍按当日覆盖的核验时间判断过期。累计金额来自已取得的历史流水。

## 接口与持久化

已有账户、总览接口增加 `funding`（含 `automatic_count`、`manual_count`）；快照增加 `margin_level`；日报增加 `winning_trades`、`losing_trades`、`breakeven_trades`、`gross_profit`、`gross_loss` 和 `win_rate`。流水返回备注及分类 `source`（automatic/manual）、自动规则 `rule_version`；`classification.revision` 用于人工校正的并发控制，尚无人工记录时为0。

| 接口 | 行为 |
| --- | --- |
| `POST /api/accounts/{id}/history/sync` | 合并回填和重查需求，返回202；不在请求内拨号 |
| `GET /api/accounts/{id}/funds` | 按服务器墙钟及流水编号倒序分页，包含余额和信用流水 |
| `GET /api/accounts/{id}/deals` | 按服务器墙钟毫秒及成交号倒序分页，返回当前单位版本已发布的 MT5 成交 |
| `PUT /api/accounts/{id}/funds/{ticket}/classification` | 追加整笔流水人工校正，要求源版本与上次人工校正版本匹配 |

流水和成交查询均支持 `limit`（1–100，默认50）和 `cursor`（取上页响应的 `next_cursor`）。资金流水支持 `unclassified=1`。分类请求含 `trade_revision`、`classification_revision`（首次为0）、`category`、`reason`。分类方向错误或信用金返回400，版本冲突返回409；客户端应重新读取流水核对。读取要求登录，写入还要求 Origin 与 CSRF。

版本5迁移建立 `history_coverage`、`history_runs`、`history_order_revisions`、`history_order_heads`、`cash_flow_classifications`，版本6增加备注、自动结果和规则版本。SDK 仅输出224字节记录中 `0x94` 起的32字节备注，依据[已有记录布局研究](research/mt4-mobile-auth-static.md#78-224b-traderecord的可用字段)，业务规则仍在主工程。

订单按账户和订单号去重，源字段（含备注）或单位变化时追加版本，同时保存该版本的自动识别结果与规则版本；重复响应不增加修订，空响应不删除历史。人工校正只追加记录。源版本改变后旧人工校正退出累计，明确的新备注会重新自动识别，无法识别则提示待确认。旧库摘要格式变化但实际源字段未变化时保留原修订与人工校正，不制造虚假的数据修订。

源版本分批低优先级暂存，读取只经过 `history_order_heads`，暂存行不可见。最后一次短事务原子切换所有当前指针、成功运行及覆盖；失败不推进覆盖。失败、重启和备份恢复清理未发布暂存，已经发布的修订及人工校正保持可见。

历史回填与校准、日报共用2个低优先级 Fetch 名额，快照保留独立10个名额；同账户由内存与数据库双重互斥。距离快照至少25秒才准入，快照前5秒结束或让位。每个发布窗口最多5,000条，超量、历史阶段资源上限或完整预算超时后二分并重新获取子区间完整响应，边界重叠1秒。连接、认证或配置阶段失败不因缩小历史窗口而改善，按原分类退避或暂停。最小2秒窗口仍失败时保留明确缺口；快照让位不触发拆分。恢复会中断运行锁并重排未完成窗口，备份恢复保留源记录和人工校正，并沿用恢复后暂停采集的规则。

本页当日统计不计算收益率和回撤；独立的[Analytics](analytics.md)负责历史 UTC 解释、资金对账、转账核对及采样收益风险分析。历史金额排序和混合流水拆分仍未提供。备注解析与自动识别只做合成验收，尚未逐个经纪商验证真实备注格式；未知格式会待识别，不能承诺所有流水无需人工。真实凭据、流水和校正依据只保存在被忽略的本地数据目录。

## MT5 成交与资金口径

- **挂单**显示剩余手数。部分成交的订单可同时有持仓和未成交挂单。连接返回止损限价单的触发价时，详情同时展示委托价与触发价。
- **成交历史**按服务器墙钟毫秒和成交号倒序，显示手数、所属订单、原始备注和费用。价格位数、成交方向和费用取自逐笔历史响应。[MT5 协议字段限制](../packages/mt5/README.md#原生-tcp)
- **当日净收益和胜率**以成交为单位。分批平仓的每笔平仓成交、反手的平仓部分及对冲平仓各计一次，撤销成交从平仓计数中剔除。开仓费用归入实际入账日的净收益，胜负和平盘由平仓成交自身的净额决定。单独入账的费用计入日结余额调整及收益分析成本。
- **出入金**沿用明确备注及人工核对规则。单独的信用金、佣金、利息和股息按成交类型记账。无法确认性质的余额操作保留待分类状态，避免把所有正负调整当作出入金。
- **收益分析**使用 `余额 + 信用金 + 持仓浮动净盈亏` 估算净值。首次确认服务器时区可选择有经纪商依据的历史生效日期。分析需要有效的历史覆盖、采样和资金分类，并显示相应缺口。

迁移 013 加入 MT5 服务器及持仓字段，迁移 014 加入 MT5 成交编号、类型、入场方式和墙钟毫秒等字段。MT4 按订单发布历史，MT5 按成交编号发布并复用历史覆盖与修订机制。迁移 017 将旧 MT5 历史覆盖重新排队，逐笔历史和日报仅发布由完整响应确认的数据。旧历史修订与人工校正保留供审计。
