# 账户交易统计与自动出入金

账户总览、账户详情均展示当日平仓、胜率、盈利/亏损、累计入金/出金和保证金水平。资金流水默认根据明确备注自动识别，人工只需校正或补充不明确的流水。金额保留账户原币；USC 不在这些指标中除以100。跨账户的美元资金小计继续使用原有确认规则，不平均账户胜率或保证金水平。

## 当日统计

“当日”采用已确认的 MT4 服务器自然日，按平仓墙钟落入 `[00:00, 次日00:00)` 归属，包含以前开仓、当日平仓的买卖记录。每条已平仓 buy/sell 历史记录计一笔；挂单、余额和信用记录不计平仓。

| 指标 | 口径 |
| --- | --- |
| 当日利润 | 所有当日平仓记录的 `Profit + Commission + Swap + Taxes` 之和 |
| 当日盈利 / 净盈利笔数 | 单笔净额大于零的金额之和及记录数 |
| 当日亏损 / 净亏损笔数 | 单笔净额小于零的绝对值之和及记录数 |
| 持平笔数 | 单笔净额为零的记录数 |
| 胜率 | 净盈利笔数 / 所有平仓笔数 × 100%，持平计入分母 |
| 当日结余 | 当日利润 + 余额调整净额，信用金另计 |

无平仓时胜率为 null，页面显示 `—`；完整空日报的金额与笔数为零。版本5之前的日报只知道已保存的净利润、结余和总笔数，胜负明细保持 null，下一次当日采集成功后补齐。费用可能使账面盈利单成为净亏损单，胜负依据净额。

保证金水平在已用保证金有效且大于零时，由后端 Decimal 计算 `账户净值 / 已用保证金 × 100%`，净值沿用包含信用金的 SDK 口径；零保证金显示“无占用”，缺失显示 `—`。API 百分比为十进制字符串，保留8位除法精度，页面四舍五入至两位。

## 历史回填与自动识别

启用采集、已有当前单位快照且服务器日期就绪后，后台自动回填协议起点至服务器当日的可返回历史。近期窗口固定为服务器自然日，每5分钟重查；已回填的较早区间约每日轮转重查。停机跨日会补建缺口窗口，详情也可点击“回填 / 重查历史”。服务器已经删除或不再返回的旧记录无法由客户端恢复。

规则 `balance-comment-v2` 根据备注中的明确标识识别外部入金、外部出金、返佣、费用、分成、内部转账和调整。支持 Deposit/入金、Withdrawal/出金、Rebate/返佣等；方向必须与类别一致，信用记录始终单独处理。只凭金额正负不能区分外部出入金与返佣等其他余额变动。

协议已确认的操作类型将余额流水统一标为 `Command=6`（balance），信用为7；服务端备注由独立的 `Comment` 字段保留。`D(DIN…)` 配合正金额识别入金，`W(DOUT…)` 配合负金额识别出金，编号部分必须为数字且括号完整。这里的 DIN/DOUT 是已识别的券商备注格式，不是额外的 MT4 通用类型。官方也将操作类型和经纪商可写入的备注列为不同字段，见[MT4历史字段说明](https://www.metatrader4.com/en/trading-platform/help/overview/terminal/terminal_account_history)。

自动结果随规则版本校验；读取旧版本结果时使用已经保存的原始备注和费用重新计算，总览、详情及待识别分页保持一致。规则升级无需再次连接 MT4，也不产生虚假的交易源修订；有效人工校正仍优先保留。

空备注、未知标识、同一备注出现多个类别、方向冲突、退款或撤销、文字编码不明确、附带单独费用的混合流水均保留待识别，不自动计入出入金。需要时可在详情点击“补充识别”或“校正”，对照到账记录说明原因。人工校正绑定源修订并优先于自动结果，仍可改回待分类；普通使用无需逐笔打开表单。

规则针对整笔净额，需要拆分的混合流水应保持待识别。内部转账本次只做类别识别，不实施跨账户配平或收益计算。

“累计入金”和“累计出金”合计当前单位、当前订单版本上自动识别或人工校正的外部资金，出金显示绝对值。返佣、费用、分成、内部转账、信用金和待识别记录不进入这两项。页面分别显示自动识别、人工校正与待识别数量；没有成功历史时为 null，已知区间尚无识别出的外部资金时显示零并保留范围与待识别提示。

历史尚未完整回填时标明“已识别部分”，失败和区间缺口不清空先前成功数据。当前服务器日的覆盖10分钟未核验时标记过期。覆盖完整只表示请求区间已经取得完整响应，金额始终截至实际采样时间，不声称当天未来活动已发生。

## 接口与持久化

已有账户、总览接口增加 `funding`（含 `automatic_count`、`manual_count`）；快照增加 `margin_level`；日报增加 `winning_trades`、`losing_trades`、`breakeven_trades`、`gross_profit`、`gross_loss` 和 `win_rate`。流水返回备注及分类 `source`（automatic/manual）、自动规则 `rule_version`；`classification.revision` 用于人工校正的并发控制，尚无人工记录时为0。

| 接口 | 行为 |
| --- | --- |
| `POST /api/accounts/{id}/history/sync` | 合并回填和重查需求，返回202；不在请求内拨号 |
| `GET /api/accounts/{id}/funds` | 按服务器墙钟、订单号倒序分页，包含余额和信用流水 |
| `PUT /api/accounts/{id}/funds/{ticket}/classification` | 追加整笔流水人工校正，要求源版本与上次人工校正版本匹配 |

流水查询支持 `limit`（1–100，默认50）、`cursor`（响应的 `next_cursor`）和 `unclassified=1`；金额排序不支持。分类请求含 `trade_revision`、`classification_revision`（首次为0）、`category`、`reason`。分类方向错误或信用金返回400，版本冲突返回409；客户端应重新读取流水核对。读取要求登录，写入还要求 Origin 与 CSRF。

版本5迁移建立 `history_coverage`、`history_runs`、`history_order_revisions`、`history_order_heads`、`cash_flow_classifications`，版本6增加备注、自动结果和规则版本。SDK 仅输出224字节记录中 `0x94` 起的32字节备注，依据[已有记录布局研究](research/mt4-mobile-auth-static.md#78-224b-traderecord的可用字段)，业务规则仍在主工程。

订单按账户和订单号去重，源字段（含备注）或单位变化时追加版本，同时保存该版本的自动识别结果与规则版本；重复响应不增加修订，空响应不删除历史。人工校正只追加记录。源版本改变后旧人工校正退出累计，明确的新备注会重新自动识别，无法识别则提示待确认。旧库摘要格式变化但实际源字段未变化时保留原修订与人工校正，不制造虚假的数据修订。

源版本分批低优先级暂存，读取只经过 `history_order_heads`，暂存行不可见。最后一次短事务原子切换所有当前指针、成功运行及覆盖；失败不推进覆盖。失败、重启和备份恢复清理未发布暂存，已经发布的修订及人工校正保持可见。

历史回填与校准、日报共用2个低优先级 Fetch 名额，快照保留独立10个名额；同账户由内存与数据库双重互斥。距离快照至少25秒才准入，快照前5秒结束或让位。每个发布窗口最多5,000条，超量、历史阶段资源上限或完整预算超时后二分并重新获取子区间完整响应，边界重叠1秒。连接、认证或配置阶段失败不因缩小历史窗口而改善，按原分类退避或暂停。最小2秒窗口仍失败时保留明确缺口；快照让位不触发拆分。恢复会中断运行锁并重排未完成窗口，备份恢复保留源记录和人工校正，并沿用恢复后暂停采集的规则。

本次不计算收益率、回撤或历史 UTC 时间重建；历史金额排序、混合流水拆分及跨账户转账配平仍未提供。新增备注解析与自动识别只做合成验收，尚未逐个经纪商验证真实备注格式；未知格式会待识别，不能承诺所有流水无需人工。真实凭据、流水和校正依据只保存在被忽略的本地数据目录。
