# 收益与风险分析

Analytics 位于侧栏“收益分析”。四个区域依次为收益与风险 KPI、收益表现、收益日历及账户贡献。支持组合或单账户、24小时/7天/30天/90天与自定义范围，中英文与手机布局；筛选保存在 URL。

## 统计范围与金额

- 默认全部已有效纳入的 USD / USC 账户，美元美分按已确认倍率换算；其他币种可选单账户原币分析，不能直接相加。
- 收益日历与日期输入使用北京时间。账户页面的“当日”采用对应 MT4 或 MT5 服务器的已确认日期。
- 请求区间最多90天，向内对齐至完整 UTC 分钟边界，至少两个相邻分钟时点。历史记录按 `[开始,结束)` 归属，端点资金事件另做估值歧义检查。
- 截止时间取可用历史成功运行的开始时间与有效快照的公共分钟边界，不能将请求的当天终点或同步完成时间当作已经发生的数据。页面同时显示实际范围与生成时间。
- 金额使用 Decimal 与十进制字符串；不在前端、SQLite REAL 或金额 TEXT 的隐式加总中计算。原始金额不提前舍入，收益率除法及每步复合明确保留24位小数。

## 四个 KPI

统计权益 `V = Equity - Credit`，保留 SDK 原始含信用金净值供账户页展示。

| 指标 | 口径 |
| --- | --- |
| 区间净收益 | `V_end - V_start - 资本净流入`；包含浮盈变化 |
| 已实现交易净盈亏 | MT4 按平仓订单汇总利润、佣金、隔夜费及税费。MT5 按成交入账汇总利润、佣金、隔夜费及已取得的手续费，含开仓费用 |
| 估算收益率 | 连续有效分钟区间按 Modified Dietz 计算，再复合连接 |
| 采样最大回撤 | 所选区间资金流调整曲线从此前峰值到后续谷值的最大跌幅 |

资金流加权公式为 `r = (V_end - V_start - ΣK) / (V_start + ΣwK)`，其中 `w = (t_end-t_event)/(t_end-t_start)`。累计收益率为 `Π(1+r)-1`。没有资金流时点的准确估值，不称为精确时间加权收益率。

归一化曲线从1开始；回撤为 `1-N/此前最高N`。峰值、谷值及恢复时间随结果提供，零回撤不制造峰谷事件。分母非正、收益率小于等于-100%或复合链失效时停止相关百分比，金额事实仍独立判断。

净收益分解为已实现交易净盈亏、浮动净盈亏变化、已确认返佣/分润收入和独立费用/分润支出。使用浮盈的期末减期初变化，不能直接加期末浮盈。

收益日历的每日主金额、盈亏颜色与月份主合计使用**已实现交易净盈亏**，按北京时间归属。浮盈变化、资金流和信用金分别显示。缺少日界估值时，完整历史仍可提供已实现收益和笔数；平仓笔数为零的 MT5 日期仍可能有开仓费用。历史、时区或单位不完整时显示待核验。[MT5 成交与资金口径](account-statistics.md#mt5-成交与资金口径)

## 资金分类与组合

外部入金、出金、确认的资本性调整和成员纳入属于资本变动；信用金通过统计权益剔除。返佣、费用、分润属于收益或成本，不能再次当作资本剔除。未知流水和“其他调整”仍待确认；资金校正入口新增“已确认资本性调整”，需填写依据。

单账户的内部转账按资本进出处理。组合内转账必须人工核对两个不同账户的当前来源版本、方向、分类版本、时间规则及换算后的相等金额。转出不能晚于转入；混合费用需先拆清。匹配证据只追加保存，来源、分类或时间规则变化后旧匹配失效。

已确认且双方均属于组合的转账，在转出至到账之间作为已知在途资金计入组合统计权益，不能制造亏损或回撤。查询起点之前发起的转账也检查，不能因切换期间而丢失在途金额。未配对的已知内部转账阻止相关组合净收益和百分比，已确认平仓盈亏保留。

新账户按其纳入时间及首份可验证快照建立资本流入，不回写此前组合。暂停采集不是移出。现有移出记录缺少可核验退出估值时，受影响净收益和百分比保持不可用，不猜测退出金额。

## 对账与完整性

[休市降频](market-rest.md)使用内置外汇/贵金属周末模板。只有相同规则版本、状态一致的前后成功快照及完整无事件的历史/时间证据共同成立时，才延续中间分钟估值，并单独统计、标注休市估算数量；不将90秒常规规则整体放宽。没有后一份快照的当前尾部保持原截止与缺口判断。组合按账户分别核验后对齐，不用跨账户原始时间差否定已核对的休市延续点。

每个 UTC 分钟优先选择该点前完成的最近样本，样本年龄及采集窗口跨度都不得超过90秒。若该样本因边界入账事件不可用，可补选该点后90秒内首份可用快照：从分钟边界至快照完成必须有完整且时间已确认的历史覆盖，期间及采集窗口不得有该账户的入账事件、单位异常或成员变化；补选后仍须通过余额与信用金对账。无后续证据、过旧或真实采样缺口不做填补。组合分别检查每个账户自己的采集窗口，不能用另一个账户的交易判定此账户估值失效；组合采样跨度仍不得超过90秒。

浮盈使用日界附近的快照报价估算，补选前后均不声称是午夜精确报价。日详情标明采样估算、边界采样最大偏移及是否使用日界后快照。旧快照缺少采集周期时，仍按实际采集起止时间、单位版本及90秒上限判断估值，单独报告周期未知数量；不回填周期。单位版本变化、缺失样本和采集偏差均有明确原因。

MT5 使用手动确认的服务器时区及其生效日期。MT4 的交易事件校准仅在有证据的有限区间使用，从已接受的原始观察重建至少3笔订单、2轮采集的有效窗口。已识别外汇/贵金属的观察在内置纽约周五18:00至周日16:00休市期间暂停24小时寿命的累计，开市后继续计时并由新成交复核；未知及加密品种不暂停，不把休市前已过期的证据延长。出现偏移冲突、配置/接入点失效或已知夏令时切换时仍停止采用旧偏移。现存证据有效期内的首次开市复核若与休市前偏移冲突，会撤销尚未由开市成交确认的跨休市延续，休市前已确认区间保留；读取历史证据时也向后检查有界的复核窗口，使单日与整段查询采用一致判断。当前校准状态过期不抹除仍有原始证据的历史窗口；新证据不反向补全此前未知的时区。收益分析、资金事件与转账核对共用这套时间解释。SQL 为查时区扩大读取的候选窗口不等于统计区间，确定无法影响请求范围及期初估值不确定窗口的旧记录不阻断当前分析。

`analytics-v7-clock-active24` 从原始观察重新构建上述窗口，不改写历史校准观察或伪造新成交。它恢复的是历史时间解释；90秒快照有效期、完整流水覆盖和资金对账要求保持原有标准，真实断采仍会限制收益率及回撤。

页面“估值覆盖”表示已有分钟估值的有效比例，不表示计算进度。计算结束后直接列出不可用指标的具体原因，并显示本区间首个有效采样时间。

统计先从原始快照构建分钟估值，绝不使用资产走势图的抽样结果；完成计算后才降低图表点数，保留端点、指标极值和连续段标识。图表遇到不同连续段必留空。缺口后的曲线是重新归一化的片段，不冒充完整区间指标。120/300秒采集可能产生较多空白分钟，不放宽标准。

资金事件具有秒级时间精度。每份估值检查快照采集开始前999毫秒、采集完成时刻及分钟标签共同覆盖的窗口；同一账户的事件落入其中时，该候选快照保持不确定。后续快照只能在其自身采集窗口与边界之间无入账事件时替代，不能猜测事件是否已记入快照。

余额变化与已入账交易净额、余额流水核对；信用金变化与信用流水另核对。初始金额容差为每户 `0.00000001` 原币，按单位倍率换算，组合累加容差。对账差额、容差及状态随结果提供，不把差额补作收益或出入金。经纪商的费用入账语义若与当前模型不符，会保留差额并阻止相关指标。

MT4 使用 SDK 的净值，MT5 使用余额、信用金和持仓浮动净盈亏估算净值。结构恒等式只检查内部一致性，独立核验仍需券商报表。历史完整指已成功发布所查区间的完整响应，范围受券商保留记录限制。

| 情况 | 处理 |
| --- | --- |
| 历史缺失或历史时间不确定 | 完整交易统计不可用，不能记零 |
| 待分类资金 | 平仓盈亏可独立展示，净收益及未确定的资金/成本小计不可用 |
| 中间快照缺失，端点与资金流水可靠 | 净收益金额仍可核对；完整收益率和回撤不可用 |
| 无有效期初或期末估值 | 净收益不可用；完整已实现盈亏仍可用 |
| 完整区间无平仓 | 平仓笔数为0；MT5 仍计入该区间的开仓费用 |
| 日历不具备完整交易依据 | 平仓笔数为 null，显示待核验 |
| 没有组合成员 | 指标不可用，不生成空组合的零收益 |

日历点击日期可查看收益分解和交易/资金流水，每页50条。详情首先展示已实现交易净盈亏，浮盈变化与含浮盈的采样净收益分别列出；估值不足的原因附在相应指标旁，不压住日历主金额。桌面和手机格子都显示已实现收益和独立的浮盈变化。北京时间23:58至00:02临时提升至30秒采样、尽量靠近零点完成短请求，以减少今后的日界估值空缺；既有缺失估值不通过历史交易反推补齐。

月份接口分别提供 `realized`、`floating_change` 和保留原口径的 `net_profit`，每个指标只依赖对应每日指标的完整性；零点估值缺失不会使完整的月份已实现收益消失。任一天交易依据不足时，月份已实现合计仍不可用，不将已知日期的小计冒充完整合计。区间首尾的部分月份明确标记。`analytics-v8-realized-calendar` 标识此口径及月份字段；区间净收益、收益率和回撤的计算规则保持原有定义。

日历的时间未确认数量按北京时间逐日判断，并包含当日期初估值的采集不确定窗口；其他日期的异常不传入当天。账户与组合使用同一日界划分。能定位时间的单位、成员变动和转账问题只影响其生效区间；尚未配对的转出仍保留后续在途风险，无法定位时间的来源问题仍保守处理。切分日历时保留期初之前和期末时点的事件作为边界证据，但交易金额、资金分类及平仓笔数仍仅统计当天 `[开始,结束)` 的流水。因此日历中的某一天与单独查询同一天使用一致的时间和边界判断；真实估值缺口仍会阻止相关净收益。

账户表同区间、同截止、同方法排序，缺失值排在可比较结果之后。组合收益率及回撤独立计算，不平均或相加账户百分比。

## 来源证据与查询接口

所有接口要求登录，响应不缓存。修改转账配对还要求 Origin 和 CSRF。

    GET /api/analytics?from_ms=…&to_ms=…&unit=USD
    GET /api/analytics?from_ms=…&to_ms=…&account_id=…&unit=native
    GET /api/analytics/activity?from_ms=…&to_ms=…&offset=0&unit=USD
    POST /api/analytics/transfers

范围参数不接受未知或重复字段。分析查询限15秒，超时503；当前修订在分批读取期间变化返回409，不发布混合版本结果。最多读取200,000条候选历史记录，超限明确报错，不截断后继续计算；流水明细限一天。

结果包含各指标的值和原因、实际范围、数据状态、对账、采样数、计算版本、来源版本和 SHA-256 证据摘要。摘要引用当前订单、有效分类、时间规则、快照和转账依据；相同依据及区间得到相同摘要。诊断的生成时间不参与收益计算。

迁移009扩充资本调整分类，保存转账核对和分析依据修订。迁移010将校准观察和相关配置变更加入分析修订检查。迁移011保存只追加的休市策略及新快照证据，策略变更加入分析修订检查，旧快照不补造休市证据。升级不改变现有金额、凭据或会话。升级前按[启动指南](product-start.md)备份；回退使用匹配旧版本的备份，不就地降低数据库版本。普通回归只操作合成数据库。
