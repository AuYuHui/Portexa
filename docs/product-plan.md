# Portexa 多账户聚合系统方案

日期：2026-11-11，Asia/Shanghai。

Portexa 从协议研究转向多经纪商、多交易账户的聚合系统。第一版协议作为冻结基线，产品功能在主工程实现，通过 `portexa/mt4` SDK 接入交易数据。

本文保存已沟通确认的产品范围、技术方向、Analytics 指标和登录规则。核心表结构已细化到 [SQLite 数据模型](product-data-model.md)，资源隔离、可信接入和保留策略见[运行与验收规则](product-runtime.md)。产品功能按阶段实施，API 契约和页面布局在对应阶段固化，不将规划能力视为现有实现。

## 产品范围

首版部署在一台私有服务器，通过电脑和手机浏览器访问，供一个用户使用。核心目标是统一查看多个交易账户的资金、持仓、盈亏和同步状态。

| 项目 | 首版范围 |
| --- | --- |
| 系统用户 | 单用户，仅密码登录，无用户名、角色和成员管理 |
| 交易账户 | 多经纪商、多账户，首批接入 MT4 只读账户 |
| 组合 | 只提供全部账户汇总，不建设自定义组合 |
| 统一计价 | 已确认单位的 USD、USC 统一为 USD，其他币种分别展示 |
| 设计规模 | 以20个账户作为首版容量验收目标 |
| 快照调度 | 默认每60秒调度一次资金和持仓采集，设置页可选30/60/120/300秒 |
| 历史调度 | 近期历史默认每5分钟补齐，首次接入后台回填 |
| 数据时效 | 每个账户显示更新时间，超过周期的3倍（至少3分钟）标记过期 |
| 协议范围 | 使用现有 SDK，不扩展交易指令、实时订阅或自动服务器发现 |

调度周期不等于数据已同时刷新。页面必须体现实际采集时间、调度延迟及失败状态；容量目标通过相关验证后再形成运行承诺。

术语区分：系统登录密码用于进入 Portexa；投资者密码用于 SDK 连接交易账户；账户净值保留 SDK 的含信用金口径；统计权益用于收益计算，剔除信用金，不代表可提现金额。

采用自建组件体系，统一表格密度、数字对齐、币种、正负号、更新时间和状态展示。筛选条件优先放入 URL，服务端数据由 Query 管理，不复制进 Pinia。

一个 Go 服务承载产品功能，调度内置于服务，前端构建产物随服务发布。浏览器访问本服务，数据库位于服务器本机；依赖版本在实际引入时固定并验证兼容性。

GORM 通过 SQLite 适配器复用由 `modernc.org/sqlite` 初始化的读写连接池。表结构、STRICT 约束、部分唯一索引、触发器及升级由版本化 SQL 迁移管理，生产启动不执行隐式 `AutoMigrate`。金额继续使用 Decimal 与 TEXT，快照及历史发布保持显式原子事务，单写连接和 WAL 规则不变。

| 模块 | 职责 |
| --- | --- |
| Account Manager | 经纪商、可信服务器、交易账户、投资者凭据、连接验证和暂停采集 |
| Sync Engine | 快照与历史分别调度，控制并发、重连、覆盖范围、去重及失败恢复 |
| Analytics | 单位归一化、资金分类、组合估值、收益、收益率、回撤和完整性判断 |

登录和会话管理属于主工程的共用基础能力，覆盖所有业务接口。后台采集独立于网页登录会话运行，退出网页不会停止同步。

协议模块继续遵守[工程结构](architecture.md)的依赖方向：业务调用 SDK，SDK 不依赖业务、数据库、网页或命令行。测试放在项目规定的 `tests` 目录，不提前创建空的业务目录。

## 单用户登录与凭据

登录页面只有密码输入框和登录按钮。系统只保存一份登录密码的加盐 Argon2id 哈希，不设置用户名、角色、成员或注册流程。

- 登录密码至少16个字符，按字符数校验，不能套用交易账户密码的字节限制。
- 首次部署在服务器本地设置登录密码；登录后可以改密，忘记密码通过服务器本地重置。
- Go 后端统一校验业务请求的会话，未登录、过期或已撤销的会话返回 `401`。
- 仅登录所需页面、接口、静态资源及不含业务信息的最小存活检查允许匿名访问；账户、持仓、历史、分析、设置及数据导出均须登录。
- 服务端管理会话，浏览器通过设置了 `HttpOnly`、`Secure` 和 `SameSite` 的 Cookie 携带会话标识。
- 使用 HTTPS，登录入口限流，修改类请求校验 CSRF；会话超时由服务端执行。
- 退出时撤销当前会话，改密或本地重置密码后撤销全部会话。前端随后清空财务数据缓存并返回登录页。

MT4 投资者密码需要供后台采集使用，因此单独加密存储，密钥与数据库分开管理。网页和 API 允许更新凭据，不提供明文回读；日志不记录密码、会话标识或接入材料。

系统登录密码与交易账户密码是独立约束。当前 SDK 要求投资者密码为1–16个 UTF-8 字节，并显式声明 `mt4.InvestorPassword`；业务侧不得将此声明解释成服务端权限证明。

真实凭据、接入地址、数据库、密钥、设备材料和报文只保存在被忽略的私有运行目录；文档、源码及测试只使用合成示例。

凭据采用独立本地密钥和 AEAD 保护，绑定账户及接入点版本；核验规则、密钥文件权限、轮换和异常验收见[可信 MT4 接入点](product-runtime.md#可信-mt4-接入点)。

## 服务器与同步

### 账户和服务器身份

可信服务器配置由已登录用户维护，包括稳定的服务器标识、经纪商归属、核验后的显示名称与接入地址，以及时间解释所需的时区规则。普通接入流程选择已有服务器，再输入交易账号和投资者密码。

交易账户由协议类型、稳定服务器标识和登录号共同识别，不能只按登录号去重。接入地址变化不应生成另一个账户；订单存储按交易账户和订单号共同去重。

当前 SDK 在读取服务器响应前已发送密码派生材料。首版接入门槛已确认为：独立核验并锁定接入点，明确确认剩余风险后启用直连。核验、账户固定关系或该修订的风险接受记录任一缺失时，关闭该连接；有效修订的正常同步与重连复用既有确认。地址变更建立新修订并重新核验、确认，不原地覆盖或自动迁移凭据。此门槛不等同于密码学服务端身份认证。

### 调度和持久化

快照采集与历史同步分别记录调度、成功时间、失败状态及恢复进度。同一账户避免重叠采集，不同账户采用受限并发，历史回填不能长期占用快照采集容量。

资源默认分为10个快照名额和2个历史名额，最多12个 Fetch，历史不借用快照名额。同账户历史只有在距下一轮快照至少25秒时才准入，并在快照前5秒结束或让位；调度、退避、写事务及恢复规则以[运行规则](product-runtime.md#同步资源与优先级)为准。

连接失败、超时的重试与退避在 Sync Engine 实现。配置非法、协议不支持、资源超限等错误按 SDK 分类展示和处理，不无限重试；服务端拒绝保留原码，不直接解释为密码错误。

`Fetch` 每次建立并关闭连接，单次调用受20秒总期限和16 MiB资源上限约束。历史分窗仍共享单次调用的总期限，大历史回填须由业务调度拆分为可独立完成的请求并保存覆盖进度。

成功的完整快照原子更新资金和当前持仓。失败或未完成结果不覆盖上次有效数据，也不将空结果当作账户已清空。

历史请求按成功提交的窗口推进覆盖范围。重查按账户和订单号更新已有记录，空窗口不删除其他窗口的数据；记录修订或资金重新分类后，重算受影响的统计。

### 完整性与截止时间

`HistoryRead`、`HistoryComplete` 和 `HistoryCovered` 描述本次请求结果。业务还需保存已提交的区间及核验时间，不能因一次请求成功就声称全部历史完整。

请求上限 `2147483647` 不能解释为未来历史已经覆盖。完整性只针对服务端实际提供、业务成功提交的范围，不能恢复服务端已删除的历史。

收益截止时间取快照与历史都已确认的公共时间。历史同步落后时，当前资金和持仓仍可刷新，但区间收益显示自己的截止时间，不能把尚未同步的资金变动当作零。

协议输入、字段和错误边界以 [SDK 约定](../packages/mt4/README.md)及[公开数据类型](../packages/mt4/types.go)为准。

## Analytics 统计基础

### 单位与金额精度

USD 保持原值；确认为美元美分账户后，按 `USD = USC / 100` 换算。保留原币、原值和换算倍率，金额换算不改变手数，也不推断不同经纪商的合约规格相同。

其他币种单独展示。USD 汇总标注“含 USC”及纳入账户数量；单位尚未确认的账户不并入该合计，并展示未纳入原因。

SDK 当前输出 `float64`。接入边界保留原值并转换为 Decimal，转换不会恢复上游已损失的精度。后续汇总不提前舍入，除法显式指定精度，美元默认显示两位小数，明细可展开更多精度，API 金额使用十进制字符串。

### 时间与统计边界

采集时间以 UTC 记录。MT4 订单的原始服务器墙钟值单独保存，结合已核验的服务器时区及夏令时规则转换；不得直接当作 UTC Unix 时间。

日、月统计默认使用北京时间，自然日和日期筛选采用半开区间 `[开始, 结束)`，避免相邻区间重复计算。收益估值与资金记录须使用一致的边界；未能对齐时标记待对账。

总览和账户详情新增的“当日利润 / 当日结余”按2026-11-11确认的需求使用 **MT4 服务器日期**，与终端历史页筛选一致；这不改变后续 Analytics 日、月报告的默认时区。服务器日界线通过新平仓事件校准当前偏移，证据不足时按已收录官方规则初始化和兜底；手动校正放在高级设置，明确保存后优先保留。金额保留原币，完整性与范围见[使用说明](product-start.md#当日利润与结余)。

缺少服务器时区时，仍可展示带标记的原始时间及当前资金，但不生成依赖日、月归属的统计。接入前历史只能支持已同步成交和资金记录分析，不能还原完整权益曲线。

### 资金与成交指标

| 指标 | 计算与数据要求 |
| --- | --- |
| 余额 | SDK `Account.Balance` |
| 信用金 | SDK `Account.Credit`，单独展示 |
| 账户净值 | SDK `Account.Equity`，保留含信用金的原口径 |
| 当前浮动净盈亏 | 当前买卖持仓的 `Profit + Commission + Swap + Taxes` 之和，保留字段符号 |
| 已实现净盈亏 | 区间内已平仓买卖记录的上述四项之和 |
| 统计权益 | `账户净值 - 信用金`，用于收益计算，不代表可提现金额 |
| 组合净值 | 对范围内账户先统一单位，再汇总账户净值，展示采集时间范围和覆盖情况 |
| 可用保证金 | 保证金有效时，计算 `账户净值 - 保证金` |
| 保证金水平 | 保证金大于零时，计算 `账户净值 / 保证金 * 100%` |

当前 SDK 的 `Command` 为0或1时代表买卖，2–5为挂单，6为余额类，7为信用类。当前买卖持仓与已平仓历史分别识别；挂单、余额类、信用类记录不混入成交盈亏。

保证金无效时显示不可用，不能用零代替；保证金为零时，保证金水平显示“无占用”。各账户资金独立，不能平均各账户的保证金百分比，也不能将汇总资金视为可跨账户抵扣。

总览合计统一标注“最近已知合计”及各账户实际采集窗口的起止范围。Analytics 只使用通过时间偏差、历史覆盖和资金对账检查的采样点，不把跨时间数值称为同一时刻精确估值，具体上限见[跨账户时间与资金验收](product-runtime.md#跨账户时间与资金验收)。

### 资金分类与组合成员变化

余额类、信用类和金额方向不足以区分外部出入金、返佣及调整。主工程按版本规则自动识别备注中明确的资金标识，无法确定的保留待识别，人工入口用于校正和补充，不要求逐笔手工分类。不能仅凭金额正负或协议类型认定全部出入金；已实现口径见[账户统计](account-statistics.md)。

| 分类 | 收益处理 |
| --- | --- |
| 外部入金与出金 | 作为资本流入、流出剔除，出入金统计单独展示 |
| 已确认返佣与独立费用 | 分别计入收益、成本，避免与订单费用重复 |
| 信用金变化 | 通过统计权益剔除信用金处理 |
| 纠错等资本性调整 | 单独记录，从净收益中剔除 |
| 内部转账 | 单独展示，确认配对；跨期在途资金未明确时暂停相关组合收益 |
| 无法确认的变动 | 标记待分类，不猜测为出入金 |

只看全部账户也必须保存账户纳入、移出的生效时间及当时估值。新账户纳入视为资本流入，正式移出视为资本流出，不能让账户数量变化制造盈利或亏损。暂停采集不等于移出组合。

历史回填不能把新纳入账户自动加入此前的组合曲线。移出后保留历史成员关系及数据，保证过去统计可复核。

## Analytics 收益与回撤

### 区间净收益

令 `V` 为不含信用金的统计权益，`K_i` 为需要剔除的资本变动，流入为正、流出为负：

`净收益 = V_end - V_start - Σ K_i`

`K_i` 包括已确认的外部出入金、账户纳入或移出，以及资本性调整。信用金已从 `V` 剔除，不重复作为资本变动扣减。

例如，期初权益1,000 USD，期间入金500 USD，期末权益1,530 USD，净收益为30 USD。

已实现净盈亏与区间净收益分别展示。区间净收益还包括浮盈变化及已确认的非成交收益、成本，不能用平仓盈亏代替。

### 估算收益率

以 Modified Dietz 为基础，对有效采样区间计算资金流加权收益率，再复合连接：

`r_k = (V_end - V_start - Σ K_i) / (V_start + Σ w_i * K_i)`

`w_i = (t_end - t_i) / (t_end - t_start)`

`w_i` 表示该资本变动在区间内停留的时间比例。按事件时间加权是本项目的估算口径；没有资金流时点估值，不将其称为精确时间加权收益率。

上例若500 USD在区间中点入金，估算收益率为 `30 / (1000 + 500 * 0.5) = 2.4%`。

`累计收益率 = Π(1 + r_k) - 1`

收益率不能简单相加。资本变动分类不明、资金记录与估值未对齐、分母非正或复合链失效时，停止输出相关百分比指标；已具备完整数据的绝对损益仍可展示。

### 采样最大回撤

归一化收益曲线初始值为1，按有效区间复合：

`N_k = N_(k-1) * (1 + r_k)`

`当前回撤 = 1 - N_k / 区间内截至当前的最高 N`

最大回撤为所选统计区间内上述回撤的最大值。例如，曲线为 `1 → 1.2 → 0.9`，最大回撤为25%。

页面使用“采样最大回撤”并标注采样频率。原始净值曲线与资金流调整后的收益曲线分别展示；前者包含资金变化，后者用于收益率与回撤。分钟采样可能漏掉分钟内极值，接入前缺少权益快照的时期不生成权益回撤。

曲线缺口保持空白，不插值或跨缺口连接为完整收益序列。完整区间指标不可计算时，可另列已覆盖片段结果，并展示其范围。

在线分钟样本默认保留90天、小时汇总730天、日汇总长期保留，交易历史和修订长期保留。清理前归档并校验原始分钟样本，避免降采样破坏收益重算和回撤复核；归档不可用时明确标记分辨率与不可重算范围，不能把粗粒度回撤标为分钟回撤。

## 数据缺失与页面状态

可用性、完整性、时效性和计算方法分别表达，允许叠加。新鲜的账户快照不意味着历史已经完整，估算指标也必须注明覆盖范围。

| 情况 | 展示规则 |
| --- | --- |
| 首次同步未成功 | `— 尚无数据` |
| 同步失败但有旧快照 | 保留旧值，展示更新时间与失败状态；超过周期的3倍（至少3分钟）标记过期 |
| 部分账户过期 | 合计标注“上次已知合计”，列出过期账户，不称为当前完整估值 |
| 部分账户从未取得快照 | 完整总计不可计算，另列已知账户小计，不把缺失账户当零 |
| 币种或单位未确认 | 原值保留，标明未纳入合计及原因 |
| 区间历史尚未完整 | 区间收益显示历史同步中；已同步部分仅作为明细或明确标注的小计 |
| 资金分类或对账未完成 | 暂停受影响的净收益、收益率和回撤，已确认成交盈亏仍可展示 |
| 服务器时区未确认 | 原始时间带标记，暂停日、月归属统计 |
| 保证金不可用 | `— 不可用` |
| 完整区间确实没有成交 | 已实现净盈亏为0；其他收益指标仍按各自数据判断 |
| 收益率分母非正 | 百分比指标不适用，不能输出无穷大或伪造零值 |
| 权益曲线存在缺口 | 图表留空，完整区间收益和回撤不冒充完整结果 |

每个指标随值提供币种、统计范围、实际截止时间、预期与纳入账户数量、覆盖范围、完整性、时效性、计算方法及不可用原因。API 的正式字段名在接口契约中确定，金额缺失使用空值，不能用零兼任缺失状态。

## 页面结构

| 页面 | 内容 |
| --- | --- |
| 登录 | 单密码输入和登录结果 |
| 账户总览 | 按币种汇总资金和净值、各账户浮盈与保证金、更新时间、异常筛选 |
| 账户详情 | 资金、当前持仓、挂单、历史成交、资金变动和同步记录 |
| 交易历史 | 跨账户查询，按账户、日期和品种筛选，服务端分页与排序 |
| 收益分析 | 净收益、已实现盈亏、资金流、净值与收益曲线、估算收益率、采样回撤、收益日历 |
| 设置 | 可信服务器、交易账户接入、投资者凭据更新、暂停采集、系统登录改密 |

账户列表可本地排序筛选；交易历史采用服务端分页、排序和筛选。所有金融指标由 Go 统一计算，前端负责展示与交互。

## 分阶段交付

### 第一阶段 登录与账户看板

交付单用户密码登录、可信服务器与交易账户管理、连接验证、周期快照、总览和持仓详情。

验收：未登录不能读取业务数据；密码至少16个字符；完成账户接入后可看到真实采集状态；单账户失败不阻塞其他账户；旧值保留且明确过期；后台同步不依赖浏览器会话。表约束、可信接入门槛、独立密钥、调度隔离、WAL 与合成备份恢复列为第一阶段 P0 验收。

该阶段形成可独立使用的账户看板，历史和高级分析无需先完成。资金与持仓快照的时间信息和原始单位从第一阶段开始保留，为后续曲线积累数据。

### 第二阶段 历史与资金统计

交付历史分窗回填、覆盖范围、失败恢复、去重与修订、交易历史查询、资金分类、已实现净盈亏及出入金统计。

验收：重查不重复计数；空窗口不清除其他数据；失败不覆盖完整结果；区间不完整时显示同步范围；待分类资金不混入已确认出入金。

该阶段形成可独立使用的历史查询和资金统计能力，不依赖收益率或回撤计算。

### 第三阶段 组合收益与回撤

交付组合估值、区间净收益、估算收益率、权益及收益曲线、采样回撤和收益日历。

验收：资本变动不制造盈利；信用金变化不计入收益；新账户纳入不扭曲过去曲线；资金记录与估值未对齐时暂停相关指标；缺失数据不被填零或拼接为完整曲线。

## 实施规格的细化顺序

第一阶段按[数据模型](product-data-model.md)和[运行规则](product-runtime.md)实现键约束、快照事务、调度配额、退避及密钥边界；主工程实现方在编码前固化登录与会话、服务器和账户 API，以及页面布局。驱动引入时锁定通过 Go 1.26兼容与 SQLite 3.51.3以上版本核验的具体版本。

进入第二阶段时，由同步与 Analytics 实现方固化历史窗口和持久化水位、时间转换规则、资金分类与修订规则、查询分页契约，并以重查、断线及空窗算例验收。

进入第三阶段时，由 Analytics 实现方固化跨账户采样对齐、估值与资金流边界、除法精度和显示舍入、指标返回契约，以相同输入可重算得到相同输出为要求。无法确定的单位、时区或资金分类必须明确显示为不可用原因。

## 验证与合成算例

| 算例 | 预期结果 |
| --- | --- |
| 2,000 USD与100,000 USC，已确认单位 | 合计3,000 USD，原币金额分别保留 |
| 期初1,000，入金500，期末1,500 | 净收益为0 |
| 期初1,000，中点入金500，期末1,530 | 净收益30，Modified Dietz估算收益率2.4% |
| 净值1,100、信用100，变为净值1,200、信用200 | 统计权益保持1,000，不因信用变化产生收益 |
| 归一化收益曲线1、1.2、0.9 | 最大回撤25% |
| 完整历史区间无成交 | 已实现净盈亏为0 |
| 同一区间未同步完成 | 区间指标不可完整计算，不以0代替 |
| 一个账户尚无快照 | 总计标记不完整，只列已知账户小计 |
| 历史窗口重叠或重查 | 同一账户同一订单不重复计数，合法修订更新原记录 |
| 退出后重用旧会话 | 返回401 |
| 修改登录密码 | 旧密码和已有会话不能继续访问 |

修改后执行 `make check`，其中包含 `GOWORK=off` 下协议模块独立测试。文档与变更同时执行 `git diff --check`，单文件不超过1000行。

普通回归使用合成数据和本机回环服务，不自动登录真实交易服务；已有线上验收记录保留原日期和范围，不作为新功能的本次运行证据。
