# 服务器搜索与接入配置

在“接入与设置 → 登记服务器”选择 MT4 或 MT5，搜索经纪商或服务器名称，核对候选 IP、端口和来源后确认接入。无可用地址时可使用“手动填写（高级）”。目录发现由主工程 `internal/discovery` 负责。

## 来源和范围

| 平台 | 搜索来源 | 登记方式 |
| --- | --- | --- |
| MT4 | MetaQuotes MT4 目录 | 使用目录返回的固定 IP、端口进行原生 TCP 接入 |
| MT5 | 第三方 MTAPI MT5 目录 | 使用目录返回的固定 IP、端口进行原生 TCP 接入 |

MT4 搜索发送查询文字和目录兼容参数，MT5 搜索向 MTAPI 发送查询文字。搜索无需交易账户凭据，也不会调用 SDK 登录。上游接口失败时，页面显示搜索错误。[MT4 目录实现](../internal/discovery/provider.go) · [MT5 目录实现](../internal/discovery/mt5.go)

目录候选需有明确端口。带端口的域名由服务端解析，按出站目标规则过滤后固定为具体 IP。没有可用接入点的条目无法通过目录登记，可改用手动入口。

## 缓存和限制

- 查询为2至80个字符，拒绝控制字符；搜索按350毫秒防抖，输入变化取消旧请求。
- 上游固定为已登记的 HTTPS 来源，验证 TLS，不接受网页传入目标 URL，不跟随重定向。
- 单次请求预算12秒，响应最多2 MiB，同时最多2个目录请求。
- 每次最多返回200台服务器，每台最多24个去重后接入点；DNS解析次数及地址数另有限制。
- 内存缓存15分钟，最多32个查询且原文总计不超过8 MiB；不缓存失败，不用过期结果创建接入。
- 返回服务端生成的随机候选 ID；确认时重新读取候选，拒绝伪造或已过期 ID。浏览器不能覆盖 IP、端口、公司或来源摘要。

搜索接口要求系统登录，登记接口同时要求 Origin 与 CSRF。没有用户或角色扩展，也没有自动执行真实账户登录的目录接口。

## 登记与修订

核对经纪商、服务器名称、IP 和端口并确认风险后，系统原子保存服务器、固定接入修订、目录来源证据和确认时间。目录登记自动计算证据摘要。

目录来源只能说明候选地址的出处。账户凭据绑定到已确认的固定修订，地址不可用时沿用该修订的失败处理。手动登记同样使用固定 IP 和端口，需提供独立核验依据及证据摘要，再确认风险。

新建目录修订时，候选须匹配原服务器名称和经纪商公司。确认后旧修订停用，相关账户暂停并取消旧任务。重新绑定账户并启用后恢复采集。

## 持久化与升级

迁移002新增 `server_directory_evidence`，以 SHA-256 为键保存目录来源、取得时间及响应原文；真实接入地址只存在于私有运行数据库和备份。它与接入修订在同一事务保存，不能留下部分已确认状态。数据库备份自动包含这些证据；密钥仍单独保管。

升级与恢复按应用的编号迁移执行。当前版本与操作步骤见[备份、恢复和重置](product-start.md#备份恢复和重置)。

## 验证

普通回归使用合成目录和受控 DNS，不查询真实交易账户。覆盖请求参数与编码顺序、目录前导格式、畸形/超限响应、重定向拒绝、非公开地址过滤、去重、缓存及过期、认证与 CSRF、候选不能由浏览器篡改、证据保存、跨服务器拒绝、新修订暂停，以及 schema1 升级和恢复。

```sh
GOWORK=off go test ./tests/discovery ./tests/app -count=1
make check
mkdir -p .local/bin
GOWORK=off go build -o .local/bin/e2e-server ./tests/e2e/server
.local/bin/e2e-server
# 在另一终端执行：
.local/venv-browser/bin/python tests/e2e/discovery.py
```

浏览器验证包括桌面、390px手机、无匹配结果、候选选择、无需手填地址或摘要、明确确认、新修订及高级手动入口。真实目录验收只搜索公开经纪商/服务器元数据，不调用 SDK `Probe` 或 `Fetch`；原始目录响应保存在被忽略的私有目录，不能提交到代码或测试。

2026-11-11 的 MT4 目录实测覆盖四家经纪商的搜索及本地产品接口，范围限于目录元数据和候选地址。当时的升级验证保留了登录设置、会话、账户配置和密钥绑定。MT5 目录的候选解析和登记由合成测试覆盖。[MT4 历史研究](research/mt4-protocol.md#官方服务器发现与名称核验补充)
