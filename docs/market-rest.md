# 休市降频与估值

入口：**接入与设置 → 采集设置 → 休市降频**。内置模板默认启用；可关闭，或在“例外账户”中选择始终使用常规周期的账户。保存后无需重启。可开启自动学习，不需要手填时区和开闭市时间。

## 内置模板

`fx_metals_weekend_v1` 使用 `America/New_York` 周五18:00至周日16:00，自动适配纽约夏令时。它是留有余量的外汇、贵金属周末采样策略，不宣称是所有券商品种的精确开闭市表。

模板依据外汇、贵金属通常24/5的交易安排选取共同休市内部区间。官方资料可参考 [D Prime 贵金属交易时间](https://www.dooprime.com/precious-metals)、[EC Markets 交易条件](https://www.ecmarkets.com/pricing/)及 [OANDA 交易时段](https://www.oanda.com/us-en/trading/hours-of-operation/)。不同品种和节假日仍可能使用其他时段，本版本不自动推断节假日。

仅在当前持仓和最近100笔已发布平仓记录中的品种均可识别为外汇或黄金、白银时使用模板。未知品种、加密品种、没有持仓且没有已识别交易的新账户保持常规采集。周末仍交易的账户可显式加入例外名单。

## 调度

- 首次进入模板时段仍使用常规周期；相邻成功快照状态一致、间隔至少30秒且没有超期或失败后，才进入休市降频。
- 休市快照最多每5分钟一轮，账户按既有相位错开；当日统计和近期历史窗口每15分钟核对。
- 开闭市边界前后保留5分钟保护，北京时间日界前后2分钟使用不慢于60秒的采样。下一次排期不能越过即将到来的保护边界。
- 手动刷新仍立即排队。历史欠账、失败退避、暂停和未确认时间的处理保持原规则。
- 已进入休市状态后发生资金、持仓、价格等状态变化，或采集失败、超过计划周期加90秒，恢复常规周期至本次窗口结束。历史发布发现当日新记录也触发恢复。
- 常规周期为60秒时，稳定休市期间的快照请求量约减少80%；首次准入、保护边界、手动刷新和异常恢复期间仍可能更频繁。

快照保存本轮实际计划周期、规则版本及财务/持仓状态摘要。总览和账户页显示“休市降频”；过期提示考虑该计划周期，真实超期仍会提示。品种判断依据账户实际已观测记录，不是券商全部可交易品种清单。

## 估值证据

90秒常规估值规则保持有效。休市分钟可以采用上一份快照的延续估值，但必须同时满足：

1. 前后两份快照都记录相同已启用规则版本，均已通过稳定状态准入，并且处于同一个固化的模板或学习窗口。
2. 余额、信用金、净值、浮盈、持仓与挂单状态摘要完全相同，单位版本相同。
3. 两份快照间距不超过前一份计划周期加90秒，每次采集窗口不超过90秒。
4. 从前一份采集窗口开始前999毫秒到后一份采集完成，历史覆盖完整、时间可解释，且没有任何入账事件、单位异常或未定位时间的相关记录。

下一份快照尚未完成、状态变化、缺少历史或时间证据时，不延续空白分钟，也不因模板显示休市而将收益记零。估值仍是采样估算；并不证明采样之间每个时刻的报价完全相同。

收益分析和组合资产走势共用这套核验条件。组合按各账户自己的窗口核验，再合并已核对的分钟估值，保留原始采样时间。已有完整端点和资金流水的净收益金额仍按原规则独立计算，不因中间缺口自动隐藏。

收益页面和日期详情显示休市延续估值数量；资产走势提示和明细标明“休市延续估值（已核对）”。仅显示当前已发布、可解释的流水。

## 配置与历史

`GET /api/settings/collection` 返回原有周期及：

- `market_rest_template`：`off` 或 `fx_metals_weekend_v1`。
- `market_rest_excluded_account_ids`：例外账户ID数组。
- `market_rest_policy_revision`：只读规则版本。
- `market_rest_learning_enabled`：自动学习开关，默认启用；模板关闭和例外账户优先。

`PUT /api/settings/collection` 保留必填 `snapshot_interval_seconds`，可同时设置模板、例外账户及学习开关；省略新字段的旧客户端不会重置休市策略。例外ID必须存在且不能重复。写入仍要求登录、Origin和CSRF。

规则变更只追加版本，从保存时生效。快照引用当时的规则，关闭模板不删除已核对的历史证据。数据库迁移011保留既有周期、账户、凭据及金额；旧快照的休市字段保持未知，不补造过去的状态摘要或休市证据。

## 自动学习

同一入口的“自动学习周末休市时段”默认启用。学习只使用新成功快照中的有效持仓当前价，不增加连接、终端或外部行情依赖；余额、费用、浮盈及仓位变化单独记录，不能冒充报价活动。空仓、零价、失败、断采或配置/单位切换不计为报价静默。

按服务器、接入点、完整品种名（含后缀）及学习周期分组。不同账户可贡献证据，但每个账户的连续流独立核验，不能用另一个账户补断采缺口。关闭再开启学习或模板会开始新的学习周期；调整常规周期或例外名单不会清空其他账户已积累的周期。

- 连续健康静默至少30分钟显示候选观察；这不是可采用的休市证明。
- 有效周末要求纽约周五16:00至周日20:00连续可比较的报价，两端各至少2次实际报价变化，连续静默至少6小时。完全冻结的价格、没有持仓、缺一侧观测均不合格。
- 最近8周中至少4个完整有效周末，前三个训练，第4个独立验证。验证周末不参与调参；训练边界波动和验证偏差均不得超过15分钟，验证窗口内不得有已观测报价变化。
- 候选边界向内保留15分钟余量，最多比内置模板每侧扩大1小时。多品种账户使用各自适用窗口的交集，缺模型或当前无可观测持仓报价的品种使用模板，未知品种保持常规采集。
- 首次可用后仅从采用时间向未来生效。模型记录算法版本、证据摘要、训练截止时间及独立验证周末。原始观测、模型、状态事件和快照采用窗口不可原地修改。
- 窗口内发现有效报价变化，在同一发布事务中暂停共享模型；本轮恢复常规频率。边界漂移、独立验证失败或证据超过8周会暂停；之后使用适用模板重新积累。保留5分钟探测及日界、边界保护，不将预测窗口当作交易许可。
- 后台每分钟启动有界评估，每轮最多4组；各组最多每小时重新核验、最多读取200000条近期证据。失败延后重试，不阻塞快照；超过上限不采用新模型。

`GET /api/market-rest/learning` 需登录，返回当前周期各组的状态、原因、有效周末数、候选和采用模型。页面显示学习中、候选、已采用、已暂停或已关闭，以及纽约时间窗口；不显示未经校准的置信百分比。关闭学习可回退模板。

数据库迁移012保留旧规则和休市快照，追加默认启用的新规则；不为旧数据补造逐品种报价、学习周数或窗口。新部署从0个有效周末积累，空仓可能一直使用模板。模型暂停、切换或关闭不抹掉已由前后快照及完整流水核对的历史估值，预测本身也不能填零收益。

## 验证与升级

运行 `make check`，另执行：

    GOWORK=off go test -race ./tests/app -run '^Test(RestLearning|MarketRest|Analytics|Collection|RunningSnapshot)' -count=1
    GOWORK=off go build -o .local/bin/e2e-server ./tests/e2e/server
    .local/venv-browser/bin/python tests/e2e/market_rest.py

测试使用合成数据，覆盖夏令时、日界、开市、未知品种、变化/失败退出、规则版本、迁移保留、完整性反例及组合跨账户对齐；浏览器覆盖中英文、桌面和390/320像素布局。

部署程序和静态资源需一起更新。解包后明确设置发布目录及前端子目录0755、文件0644、二进制0755；停止旧服务前，先以服务运行账号确认前端可读。升级前备份数据库，失败回退旧二进制时同时恢复匹配旧模式的备份，并处理连续启动失败引起的服务启动限流。数据库模式升级到12，不能只切回旧二进制读取新库。
